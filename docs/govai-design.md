# 政务AI融合设计

## 1. 设计原则

政务AI不是单独加一个聊天机器人，而是嵌入到城市治理流程中：

```
多源数据 → 事件总线 → 风险识别 → 仿真推演 → AI解释 → 政务建议 → 人工确认 → 执行反馈
```

## 2. 三类AI能力

### 2.1 预测AI
- AQI预测
- 建筑负荷预测
- 交通流预测
- 水位预测
- 拥堵趋势预测

### 2.2 仿真AI
- 信号配时优化
- 内涝扩散模拟
- 交通诱导模拟

### 2.3 决策AI
- 基于政务知识库生成可解释建议
- 标注依据来源
- 预案检索与处置建议

## 3. AI大模型服务

### 3.1 功能
- 告警根因分析
- 多源数据摘要
- 政务报告生成
- 自然语言查询城市运行状态
- 预案检索与处置建议生成

### 3.2 实现方式
- 主路径：接入阿里云百炼（DashScope）通义千问大模型（默认 qwen-plus），通过 dashscope-sdk-java 调用
- RAG：知识库检索结果作为上下文注入提示词，保证回答有据可依
- 降级：未配置 API Key（环境变量 DASHSCOPE_API_KEY）或云端调用失败/超时时，自动降级为本地模板生成，保证服务可用
- 配置：application.yml 中 sky.dashscope.* 控制启用开关、模型、超时（默认60秒）

## 4. 知识库

### 4.1 内容
- 应急预案
- 排水调度规则
- 建筑节能标准
- 交通信号控制规范
- 城市内涝处置流程

### 4.2 检索
- 基于关键词匹配
- 基于语义相似度
- 基于事件类型分类

## 5. 决策流程

```
事件触发 → 告警生成 → AI解释 → 预案匹配 → 建议生成 → 人工审批 → 执行反馈
```

## 6. 合规校验

- 信号灯控制规范检查
- 排水调度规则检查
- 建筑节能标准检查
- AI建议不替代人工审批
